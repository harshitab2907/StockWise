Problem Statement
2
Key Challenges in College Inventory Management:
  • Inefficient Manual Tracking: College hardware components (Arduino, Raspberry Pi, sensors, multimeters) are traditionally logged using paper registers or disconnected spreadsheets, causing records to desync and items to go missing.
  • Unpredictable Demand Surges: Student requests surge heavily right before semester practical exams, lab assessments, and hackathons, leading to sudden stockouts that disrupt academic coursework.
  • Lack of Accountable Stock Issuance: Equipment is issued without automated real-time verification, resulting in double-allocations, unrecorded deficits, and zero accountability.
  • Budget Wastage & Ineffective Restocking: Absence of consumption foresight leads to over-purchasing slow-moving items while high-demand components remain critically out of stock.
  • Need for Explainable Intelligence: Academic faculty and lab auditors require a deterministic, mathematically transparent forecasting model rather than an opaque black-box machine learning system.
Project Objectives and Scope
3
Core Project Objectives:
  • Modular Core Java Architecture: Engineered using Java 17 LTS, layered architecture, OOP encapsulation, and Inversion of Control via AppContext with zero external dependencies.
  • Atomic Stock Consistency: Guarantees stock is deducted exactly once upon request approval; prevents negative inventory and rolls back state if stock is insufficient.
  • Explainable 3-Month Moving Average Predictor: Calculates Predicted Demand = (Q1 + Q2 + Q3) / 3. Strictly verifies monthly coverage and marks missing data as INSUFFICIENT_HISTORY without guessing.
  • Smart Restocking Intelligence: Computes MAX(0, ceil(Predicted + Safety - Current)) and automatically triggers high-demand warnings when predicted consumption exceeds stock.
Project Scope & Evaluation Roadmap:
  • Evaluation 1 (Current Scope): In-memory collection storage, interactive console UI, 28 automated tests (100% pass), and complete audit logging.
  • Evaluation 2 (Upcoming Milestone): Seamless database persistence via MySQL & JDBC using existing repository interfaces without changing business logic.
Hardware and Software Interface
4
Hardware Interface Requirements:
  • Host / Client Platform: Standard Laptop or Desktop PC (macOS, Windows 10/11, or Linux).
  • Processor Architecture: 64-bit multi-core CPU (Intel Core i3/i5/i7, AMD Ryzen, or Apple Silicon M-Series).
  • Memory & Storage: Minimum 4 GB RAM (8 GB recommended); 200 MB free disk space for JDK runtime.
  • Input / Output Devices: Standard Keyboard and Display Monitor for interactive console terminal operations.
Software Interface & Technology Stack:
  • Operating System: Platform-independent bytecode execution across macOS, Windows, and Linux.
  • Programming Language: Java SE 17 LTS (Core Java, standard runtime library only; 0 external JARs).
  • Data Persistence Layer: In-Memory thread-safe Java Collections (LinkedHashMap, ArrayList, TreeMap).
  • Version Control & Automation: Git & GitHub repository, Unix automation scripts (compile.sh, run.sh, test.sh).
  • Automated Test Suite: Zero-dependency custom assertion runner (TestRunner, 28/28 tests passing).
